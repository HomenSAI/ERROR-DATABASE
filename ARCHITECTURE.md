# Архитектура базы ошибок HomenS.AI

Версия архитектуры: **1.3** от 13.11.2026 (библиотека и сборка выпуска — §6–§7, §11.2). Решение владельца: Rent, DECISIONS.md 28.10-288.

## 1. Главное правило
**Эта база — единственный источник кодов ошибок для всех продуктов HomenSAI.** Это Rent, JobPilot Pro, HomenS.AI Core, Auto VPN, SECURITY-MODULE и все будущие продукты.

- Продукт не придумывает и не генерирует свои коды. Сначала код появляется здесь, потом продукт его использует.
- Продукт показывает пользователю тексты отсюда: что случилось, что делать, кому передать.
- Проверка продукта перед выпуском ищет в коде все использованные коды. Если кода нет в закреплённой версии базы, выпуск остановлен (§7.4).

## 2. Как это делают другие — образцы
| Образец | Что взяли |
|---|---|
| **RFC 9457 «Problem Details for HTTP APIs»** (IETF, 2023, заменил RFC 7807) | Ответ API с ошибкой — стандартный JSON: `type` (ссылка на описание), `title`, `status`, `detail`, `instance`. Код из базы кладётся в `type` и в поле-расширение `code` (§6.3) |
| **Google AIP-193 «Errors»** | Кроме кода, у ошибки есть устойчивое машинное имя `reason` в UPPER_SNAKE_CASE в рамках `domain`, плюс `metadata`. У нас: `key` и пространство (§3) |
| **Stripe API errors** | У каждой ошибки ссылка на страницу документации `doc_url` и понятный текст. У нас: `help` (§4) |
| **Rust error index (`rustc --explain E0308`)** | У каждого кода — страница с объяснением и примером, код никогда не переиспользуется. У нас: страница помощи на каждый код, неизменность (§5) |
| **PostgreSQL SQLSTATE** | Коды сгруппированы по классам — первые символы задают область. У нас: область `AREA` в коде (§3) |
| **Каталог JobPilot Pro (`catalog.lock`) и Auto VPN (`ERROR_CODES.md`)** | Закрепление версии каталога в продукте и тексты «что делать» для пользователя |

## 3. Формат кода
```
<ПРОСТРАНСТВО>-<ОБЛАСТЬ>-<НОМЕР>
RENT-DR-001     SEC-AUTH-012     JP-MAIL-003     COMMON-NET-001
```
- **ПРОСТРАНСТВО** — продукт или модуль: `COMMON`, `CORE`, `RENT`, `JP` (JobPilot), `VPN`, `SEC` (SECURITY-MODULE). Новое пространство заводится в `namespaces.json` до первого кода.
- **ОБЛАСТЬ** — 2–8 латинских заглавных букв или цифр. Список областей пространства ведётся в том же файле, например `RENT`: `BILL` (счета), `PAY` (оплаты), `DR` (копии), `READ` (показания).
- **НОМЕР** — три цифры, по порядку внутри области, без пропусков.

Дополнительно у каждого кода есть:
- **`key`** — устойчивое машинное имя в UPPER_SNAKE_CASE, как `reason` в AIP-193, например `BACKUP_PASSWORD_CHECK_OVERDUE`. По нему продукт ищет код в своём коде, и он не меняется.
- **`aliases`** — прежние коды продуктов, чтобы старые журналы и тексты находили запись: `DR-270-OVERDUE` (Rent), `runner_unavailable` (JobPilot).

## 4. Запись об ошибке
Одна запись — один код. Все тексты пишутся на четырёх языках: `ru`, `uk`, `en`, `de`.

| Поле | Обяз. | Смысл |
|---|---|---|
| `code`, `key` | да | §3 |
| `aliases` | нет | прежние коды |
| `level` | да | `info` — к сведению; `warn` — внимание; `error` — действие не выполнено; `alarm` — опасность, мигающая тревога |
| `audience` | да | кому показывается текст: `user` (пользователь), `admin` (администратор), `developer` (разработчик) |
| `title` | да | одна строка: что случилось, понятным языком |
| `cause` | да | почему так бывает: 1–3 предложения без жаргона |
| `action` | да | что делать: нумерованные шаги для того, кто видит ошибку |
| `escalation` | да | кому передать, если шаги не помогли (§4.1) |
| `params` | нет | подстановки в тексты, например `{days}`, `{copy}`, с типом; ничего личного |
| `retryable` | да | `true` — можно повторить действие позже |
| `http_status` | нет | статус для API (RFC 9457) |
| `help` | да | якорь страницы помощи: `errors/RENT-DR-001` или страница меры |
| `related` | нет | связанные коды |
| `since` / `deprecated` / `replaced_by` | `since` да | версия базы, в которой код появился, устарел или чем заменён |
| `tags` | нет | для поиска: `backup`, `password`, `network` |
| `fixed_in` | нет | в какой версии продукта ошибка программы исправлена: `{"rent": "1.4.2"}`. Продукт старее — показывает «обновите до 1.4.2» (§11) |
| `examples` | нет | только для `audience: developer`: путь к файлу `examples/<code>.md` с примером «как воспроизвести → как исправить»; примеры проверяются в CI (§11) |

### 4.1. Кому передать (`escalation`)
Это лестница от простого к сложному. Продукт показывает следующую ступень, если предыдущая не помогла.

```json
"escalation": [
  {"to": "self",      "when": "всегда первым"},
  {"to": "admin",     "when": "нет прав или не помогло"},
  {"to": "ai",        "assistant": "any", "prompt": "analyze-error/v1", "data": ["code", "params", "app_version", "os"]},
  {"to": "developer", "channel": "support-bundle", "data": ["code", "params", "app_version", "os", "log_excerpt_redacted"]}
]
```
- **`self`** — сам пользователь по шагам `action`.
- **`admin`** — администратор хозяйства или компании.
- **`ai`** — нейросеть-помощник. Продукт открывает встроенного помощника или копирует готовый запрос по шаблону `prompts/<prompt>.md`. В запрос попадают только поля из `data`. `assistant`: `any` — любая; `local` — только локальная модель, если данные чувствительные.
- **`developer`** — разработчик через пакет поддержки (support bundle). Перед отправкой продукт показывает пользователю, что именно уходит.
- Поле `data` — **белый список**. Личных данных, паролей, ключей и сумм в нём нет никогда. Журнал в пакете поддержки проходит обезличивание.

### 4.2. Как писать тексты
- `title` — до 80 знаков, без кода и без слова «ошибка», если и так понятно. Хорошо: «Пароль копий давно не проверялся». Плохо: «Ошибка DR-270».
- `cause` — человеческим языком, без внутренних названий модулей и таблиц.
- `action` — глаголы в повелительном наклонении, по одному действию на шаг, кнопки называются так, как на экране.
- Без страха и без вины пользователя: «Программа не смогла…», а не «Вы ошиблись…».
- Все 4 языка переводятся по смыслу, не дословно; подстановки `{...}` — одинаковые во всех языках.

## 5. Неизменность и версии
- Код **никогда** не переиспользуется и не меняет смысл. Если смысл изменился — заводится новый код, старый получает `deprecated` и `replaced_by`.
- Версии базы — semver, тегами `vX.Y.Z`:
  - **patch** — исправлен текст или перевод;
  - **minor** — добавлены коды, области, пространства или поля, необязательные для продуктов;
  - **major** — изменился формат файлов или API. Удалить код нельзя даже в major.
- `CHANGELOG.md` перечисляет новые и устаревшие коды в каждом выпуске.

## 6. Хранение и выпуск
### 6.1. Исходники (то, что правят люди и ИИ)
```
namespaces.json                 пространства и их области
codes/<NS>/<AREA>.json          записи одной области (схема: schema/error-file.schema.json)
prompts/analyze-error/v1.md     шаблоны запросов к нейросети
schema/                         JSON-схемы файлов и выпуска
tools/validate.py               проверка (без внешних зависимостей)
tools/build_dist.py             сборка выпуска dist/ (§6.2)
tools/gen_constants.py          константы кодов для Python и TypeScript (§11.2)
src/homensai_errors/            библиотека Python (§7.2), тесты — tests/ (pytest, без сети)
```

### 6.2. Выпуск (то, что берут продукты)
При теге собирается каталог `dist/` и прикладывается к GitHub Release:
- `errors.json` — все коды;
- `errors.<NS>.json` — по пространствам;
- `errors.<lang>.md` — справочник для людей;
- `help/<lang>/<code>.md` — страницы помощи;
- `search.<lang>.json` — индекс для поиска;
- `llms.txt` — вся база одним текстом для нейросети (§11.7);
- `prompts/<имя>/vN.md` — шаблоны запросов к нейросети для ступени `ai` (§4.1);
- `SHA256SUMS` — контрольные суммы всех файлов (`sha256sum -c SHA256SUMS`).

Сборка — `python tools/build_dist.py` (версия — первый заголовок `## X.Y.Z` в `CHANGELOG.md`). Она детерминирована: без дат, порядок по коду, UTF-8 и `\n`, поэтому повторная сборка даёт те же байты; это проверяют тест и задание выпуска.
`dist/` в Git не хранится (`.gitignore`). Задание `.github/workflows/release.yml` при теге `vX.Y.Z` на self-hosted runner владельца `[self-hosted, Linux, X64, rent-docker]` проверяет базу и тесты, собирает `dist/` дважды со сверкой байтов, сверяет тег с `CHANGELOG.md` и прикладывает к GitHub Release файлы верхнего уровня `dist/` и архив всей папки `homensai-errors-X.Y.Z.tar.gz` (с `help/` и `prompts/`, воспроизводимый).

Формат `errors.json` и `errors.<NS>.json`: `{"format": 1, "database", "version", "languages", "namespaces", "codes": [...]}`; записи — в порядке полей схемы. Файл `errors.<NS>.json` есть у каждого пространства из `namespaces.json`, даже пока в нём нет кодов.

### 6.3. Ответ API (RFC 9457)
```json
{"type": "https://homensai.github.io/ERROR-DATABASE/errors/RENT-DR-001",
 "title": "Backup password not checked for a while", "status": 409,
 "detail": "The check was due 3 days ago. If the password is forgotten, backups cannot be opened.",
 "instance": "/security#backups", "code": "RENT-DR-001", "key": "BACKUP_PASSWORD_CHECK_OVERDUE", "retryable": true,
 "legacy_codes": ["DR-270-OVERDUE"]}
```
- `type` — адрес кода на сайте-справочнике (GitHub Pages, решение 28.10-321) без языка и версии: это устойчивый идентификатор вида ошибки (RFC 9457 §3.1.1). Страница на языке — `<сайт>/<lang>/errors/<код>`. До 1.3 здесь была ссылка на `dist/` в Git, но `dist/` в Git не хранится (§6.2).
- `status` — переданный продуктом или `http_status` записи; если нет обоих, поле не выводится. `title` и `detail` (= `cause` с подстановками) — на языке запроса.


## 7. Как продукт подключает базу — API
### 7.1. Манифест и lock-файл в продукте
`errors.manifest.json` — что нужно продукту:
```json
{"database": "HomenSAI/Error-database", "version": "^1.0.0", "namespaces": ["COMMON", "CORE", "RENT", "SEC"], "languages": ["ru", "uk", "en", "de"],
 "transition": {"show_legacy_codes": true}}
```
`transition.show_legacy_codes` — переходный период, §12.

`languages` может быть подмножеством четырёх языков базы, например RU и EN в пакете роутера Auto VPN, где мало места. В базе и на сайте всегда остаются все 4 языка.

**Запись в базу от продуктов.** Сессия продукта работает в ветке `<пространство>/<тема>` (например `vpn/mon`) и меняет только своё пространство `codes/<NS>/*` и его области в `namespaces.json`. Общие коды `COMMON-…` добавляются только через форму Issues. Ревью и слияние делает координатор базы.
`errors.lock` — что закреплено: точная версия, список файлов и их SHA-256: `{"database": "HomenSAI/Error-database", "version": "1.1.0", "files": {"errors.COMMON.json": "<sha256>", "errors.RENT.json": "<sha256>"}}`; имена — относительно `vendor/errors/`, создаётся `homensai_errors.make_lock`. Обновление базы — явная команда разработчика с проверкой; само по себе оно не происходит.

**Сборка самодостаточна (указание владельца 09.11.2026 09:07).** При сборке продукта нужные файлы выпуска копируются внутрь продукта, в папку `vendor/errors/`, и входят в установщик:
- за кодами программа никогда не ходит в сеть — ни при запуске, ни при ошибке;
- сборка проверяет SHA-256 вложенных файлов по `errors.lock` и останавливается, если файлы отличаются или нет нужного пространства;
- ссылки «Подробнее» ведут на страницы помощи внутри продукта; ссылка на GitHub — только дополнительная.

### 7.2. Библиотека (Python — сейчас; JS/TS — для веба и расширений)
```python
from homensai_errors import Catalog, AppError

catalog = Catalog.load("vendor/errors")            # по errors.lock, со сверкой SHA-256
entry = catalog.get("RENT-DR-001")                  # также по key или по старому коду
text = catalog.render("RENT-DR-001", lang="uk", params={"days": 3})   # title, cause, action, escalation
problem = catalog.to_problem("RENT-DR-001", lang="en", status=409, instance="/security#backups", params={"days": 3})
page = catalog.help_page("RENT-DR-001", lang="ru")  # Markdown для раздела помощи
hits = catalog.search("пароль копий", lang="ru")    # для поиска в помощи

raise AppError("RENT-DR-001", days=3)              # продукт бросает только коды из каталога
```
- Неизвестный код — `COMMON-SYS-001` («Неизвестная ошибка программы») и запись в журнал разработчика. В тестах продукта это падение.
- Подстановки проверяются по `params`: лишние и недостающие — ошибка в тестах.
- **Режимы (1.3).** `Catalog.load(..., strict=True)` — для тестов продукта: неизвестный код — `UnknownCodeError`, неверные подстановки — `ParamsError`. `strict=False` (по умолчанию) — для работы: замена на `COMMON-SYS-001` с записью в логгер `homensai_errors`, недостающие подстановки остаются `{имя}`. `homensai_errors.configure(catalog)` задаёт каталог для `AppError`; без него `AppError` сверяет код со встроенными константами и строго.
- `AppError` принимает только строку вида `NS-AREA-NNN`: ключ, старый код или текст — сразу `ValueError`.
- `Catalog.load` ищет `errors.manifest.json` и `errors.lock` в папке каталога и до двух уровней выше (`vendor/errors` → корень продукта). Пространство `COMMON` загружается всегда (запасной код). Язык не из манифеста — запасной (`en` или первый язык манифеста); `uk-UA` → `uk`.
- `search` находит по коду, старому коду, `key`, началу кода (`RENT-DR` — вся область) и словам на языке (все слова запроса, простая основа слова); индекс `search.<lang>.json` строится той же функцией.

### 7.3. Встраивание в помощь
- У каждого кода — страница `/help/errors/<code>`: что случилось, почему, что делать, кому передать, связанные коды. Страницы строятся из `help/<lang>/`.
- Окно ошибки на любом экране показывает `title`, шаги и кнопки «Подробнее» (страница помощи) и «Передать…» (следующая ступень `escalation`).
- Поиск помощи использует `search.<lang>.json`: находит по коду, по старому коду, по словам.
- Страницы «Если случилось» и страницы мер ссылаются на коды через `related`.

### 7.4. Проверки в продукте
- Тест «все коды из каталога»: сканер исходников ищет `AppError("…")` и строки вида `NS-AREA-NNN`. Каждый найденный код должен быть в закреплённой версии.
- Тест «нет самодельных кодов»: литералы, похожие на код, но отсутствующие в каталоге, останавливают выпуск.

## 8. Как добавить код
1. Найти, нет ли подходящего кода (поиск по `key`, `tags`, текстам).
2. Взять следующий номер в области; новая область — сначала в `namespaces.json`.
3. Заполнить все поля и 4 языка по §4.2.
4. Запустить `python tools/validate.py` — проверяются схема, уникальность кодов, `key` и `aliases`, все языки, одинаковые подстановки, номера без пропусков.
4a. Обновить константы: `python tools/gen_constants.py` (файл `src/homensai_errors/codes.py` входит в коммит), затем `python -m pytest -q`.
5. Pull request → проверка CI → ревью → слияние → выпуск с новой minor-версией.

## 9. Что нельзя публиковать
Репозиторий открытый. Нельзя:
- внутренние пути, имена таблиц, SQL, адреса серверов;
- секреты, ключи, личные данные, суммы клиентов;
- детали, которые помогают обойти защиту: точные пороги, логика обнаружения, порядок проверок.

Такие заметки разработчик держит в закрытом репозитории продукта. Здесь остаётся только то, что увидит пользователь.

1. **Сайт-справочник** на GitHub Pages, бесплатно для публичного репозитория. На каждый код своя страница, на 4 языках; поиск по коду, старому коду и словам. Как Twilio Error and Warning Dictionary и Rust error index. Собирается из `dist/` при каждом выпуске.
2. **Константы для кода.** Из базы генерируются `homensai_errors/codes.py` и `codes.ts` (`python tools/gen_constants.py`; для продукта — `--source vendor/errors --manifest errors.manifest.json --py … --ts …`; `--check` — для CI): `Errors.RENT_DR_001`, `Errors.BACKUP_PASSWORD_CHECK_OVERDUE`. Опечатка в коде ловится проверкой типов до запуска — как константы, которые TypeScript генерирует из `diagnosticMessages.json`.
3. **«Исправлено в версии»** — поле `fixed_in`, §4.
4. **Примеры для разработчика** — поле `examples`. Как у Rust: каждый пример «воспроизвести → исправить» проверяется автоматически.
5. **Кнопки «Помогло» / «Не помогло»** под текстом ошибки в продукте. Счётчики хранятся только на компьютере пользователя и попадают в пакет поддержки только вместе с ним. По ним видно, какие тексты надо переписать.
6. **Форма «предложить код»** — шаблоны GitHub Issues: новый код, исправление текста или перевода. Предложить может любая сессия ИИ или человек.
7. **Файл для ИИ `dist/llms.txt`** — все коды одним текстовым файлом: код, `key`, заголовок, что делать на 4 языках. Нейросеть загружает базу целиком одним запросом.
8. **Анонимная статистика частоты** — по желанию пользователя, по умолчанию выключена. Отправляются только код, версия продукта и число раз за период — без данных, без идентификаторов, без IP в журналах приёмника. Цель — сначала чинить самое частое.

## 12. Переходный период: новый и старый код вместе (решение владельца 09.11.2026 09:19)
Пока продукты переходят на базу, ничего не должно теряться. Поэтому везде, где показывается или записывается ошибка, идут **оба кода и полное описание** — в окне ошибки, на странице помощи, в журнале, в пакете поддержки, в ответе API.

- **Порядок:** сначала новый код, потом старый, потом описание:
  ```
  RENT-DR-001 (прежний код: DR-270-OVERDUE)
  Пароль копий давно не проверялся
  Почему: … · Что делать: 1. … 2. … · Кому передать: …
  ```
- **Откуда старый код:** из `aliases` записи. Если старых кодов несколько, выводятся все через запятую.
- **API (RFC 9457):** рядом с `code` — поле `legacy_codes: ["DR-270-OVERDUE"]`.
- **Журнал продукта** пишет оба кода. Поиск в журнале, в помощи и на сайте находит запись и по старому, и по новому коду.
- **Как включается:** настройкой `transition.show_legacy_codes` в `errors.manifest.json` продукта. Во время перехода — `true` для всех продуктов. Библиотека `Catalog.render`/`to_problem` по этой настройке добавляет старые коды сама, продукту ничего делать не нужно.
- **Конец переходного периода** объявляет владелец — для всего продукта сразу. После этого настройка становится `false`. Старые коды по-прежнему остаются в `aliases` и в поиске, но перестают выводиться рядом с новыми. Сами `aliases` не удаляются никогда.
