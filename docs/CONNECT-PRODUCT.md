# Как подключить продукт к базе ошибок (API базы)

Решение владельца 15.11.2026: во всех продуктах HomenSAI коды ошибок берутся **только** из этой базы. Документ — короткая инструкция для разработчика и ИИ-агента; подробности — `ARCHITECTURE.md` §3.1, §7, §9, §12, `namespaces.json`, `AGENTS.md`, `CHANGELOG.md`.

## 1. Что такое код
- **Буквенный код** `<ПРОСТРАНСТВО>-<ОБЛАСТЬ>-NNN` (например `RENT-FX-003`, `VPN-PAIR-007`, `SEC-KEY-002`) — основной. Никогда не переиспользуется и не переименовывается.
- `key` — устойчивое машинное имя; `aliases` — прежние коды продукта (переходный период, §12).
- **Цифровой код** `number` = `PPP-AAA-NNN`, ровно 9 цифр (версия базы 1.2.0):
  - PPP — номер продукта (`namespaces.json` → `number`): COMMON 001, CORE 002, RENT 003, JP 004, VPN 005, SEC 006;
  - AAA — номер области (`area_numbers` пространства);
  - NNN — номер из буквенного кода.
  - Примеры: `RENT-FX-003` → `003-012-003`; `VPN-PAIR-007` → `005-001-007`; `SEC-KEY-002` → `006-002-002`.
- Номера продуктов, областей и ошибок не переиспользуются. Новая область получает следующий свободный номер. Номер ошибки — 001…999 без пропусков; при подходе к 999 область делится (новая область со следующим номером).

## 2. Единственный источник
- Каталог — `codes/<ПРОСТРАНСТВО>/<ОБЛАСТЬ>.json`; публичный справочник — https://homensai.github.io/ERROR-DATABASE/ .
- Самодельные коды в продукте запрещены, в том числе «временные» и в тестах. Нужен код — добавить его в базу.
- Если у продукта ещё нет пространства — запросить новое пространство в базе (следующий свободный `number`), не придумывать коды локально.

## 3. Как добавить код (только в базе)
1. Найти, нет ли подходящего (поиск по `key`, `tags`, текстам, `aliases`).
2. В `codes/<NS>/<AREA>.json` взять следующий номер области; записать `number` сразу после `code`. Новая область — в `areas` и `area_numbers` в `namespaces.json`.
3. Тексты на ru/uk/en/de: `title`, `cause`, `action` и `escalation`, а также `level`, `audience`, `retryable`, `help`, `since` — по `schema/error-file.schema.json`. Пользователь без технических знаний должен понять, что случилось и что делать. Без адресов, IP, ключей, путей, внутренней логики и персональных данных (§9).
4. `python tools/validate.py` — 0 ошибок; `python -m pytest -q` — зелёное; `python tools/gen_constants.py`; запись в `CHANGELOG.md`.
5. Перед каждым коммитом — `git pull --rebase`: в базу пишут и другие сессии. Работа продукта идёт в ветке `<пространство>/<тема>` и меняет только своё пространство; общие `COMMON-…` — через Issues; слияние делает координатор базы (§7.1).
6. Коммит: автор `Serhii Khomenko | HomenS.AI <info@homensai.com>`, коммитер `Claude <noreply@anthropic.com>`.

## 4. Как подключить базу к продукту (образец — Homensai-Rent)
- В репозиторий продукта кладутся файлы из `dist/` выпуска: `errors.<NS>.json` своего пространства, `errors.COMMON.json`, `errors.manifest.json` и `errors.lock` с SHA-256 (обычно в `vendor/errors/`).
- При сборке коды вшиваются в продукт: он работает без сети и за кодами никуда не ходит.
- Сборка и тесты сверяют хэш файлов с `errors.lock`; несовпадение или отсутствие нужного пространства останавливает сборку.
- Обновление базы в продукте — явная команда разработчика (`homensai_errors.make_lock`), сама по себе не происходит.
- Продукт выдаёт только коды из каталога (`AppError("<код>", ...)`); неизвестный код — `COMMON-SYS-001`.

## 5. Что показывает интерфейс
- Текст ошибки на языке пользователя, буквенный код, **цифровой код** («Цифровой код 005-001-007») и ссылку `https://homensai.github.io/ERROR-DATABASE/errors/<КОД>`.
- Прежний код допускается в скобках как «прежний код» (переходный период, §12).

## 6. Тесты продукта
- каждый выдаваемый продуктом код есть в базе (сканер исходников, §7.4; «самодельный код» останавливает выпуск);
- цифровой код в продукте совпадает с базой;
- файлы совпадают с `errors.lock`;
- в интерфейсе показан цифровой код.
